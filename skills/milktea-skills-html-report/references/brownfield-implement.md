# 既有系統重構結案報告契約

## 用途與產生時間

證明本次核准重構已完成，而且 Planner 指定的原有功能與相容性沒有被破壞。只有呼叫者識別為 `brownfield-implement`，所有 Tickets、Review、修正、定向複驗、原有功能確認與最終總驗收均完成時才能產生。

固定寫入 `<實際工作目錄>/completion-report.html`。產生前檔案必須不存在；驗證通過後不得覆寫。

## 必要輸入

- 工作識別碼、繁體中文顯示名稱與實際工作目錄。
- Planner HTML、核准方案、Spec、全部 Tickets、實際差異與版本。
- 必須保留功能、修改前基準、修改後相同方法驗證及相容性結果。
- 測試、Reviewer、Finding、修正、定向複驗、清理處置及未解風險。
- 每張 Ticket 的前端實際操作適用性、判定依據與實際證據。

## 需求與相容性驅動內容

報告使用彈性 HTML 外殼，不強迫固定專案章節。至少回答：

1. 最終結論：核准重構與相容性是否全部通過。
2. 原始重構目標：逐項顯示核准目標、範圍、實際結果與證據。
3. Ticket 成果：白話說明每張 Ticket 的處置、Review 結論、清理結果及是否偏離核准方案。
4. 實際驗收：回歸測試、退出碼、原生瀏覽器操作或不適用依據、Findings 關閉情況，以及每項必須保留功能的修改前後證據。
5. 風險與回復：未知區域、未解風險、觸發條件、降低方式、回復步驟及回復後相容性驗證。
6. 使用者確認：依核准目標與必須保留功能提供逐項可勾選清單；這是使用者清點工具，不取代 Agent 已完成的技術驗收。

只有真實資料足夠時才增加架構差異、清理統計、改善數據或圖表。缺少可靠基準時使用「無法量化：缺少修改前基準」，不得製造數字。

## 狀態用語

核准目標狀態只使用「完成、部分完成、未完成、範圍外」。本報告只有全部核准目標及必須保留功能均完成且驗收通過時才能產生。

## 聊天框

只顯示「重構與相容性驗收通過」及結案報告絕對路徑連結，不逐票重述證據。
