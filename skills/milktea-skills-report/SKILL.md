# 奶茶流報告呈現

只整理報告的呈現方式。必填內容、證據要求、儲存位置、核准與交付流程均沿用呼叫方；不新增報告、副本或核准關卡，不因精簡而省略必填資訊。呼叫方有更具體的報告契約時，保留其要求。

## 表達規則

- 全文使用繁體中文與白話短句；程式識別字、技術名稱、命令與實際路徑保留原文。
- 開頭直接說明本次範圍、結論或成果，以及需要使用者決定或確認的事項，省略長篇前言與操作流水帳。
- 選擇能說清楚重點的最小表示方式；一句話足夠就用短句，不為視覺化硬畫圖，也不硬湊章節或圖表數量。
- 一個概念只說一次，圖表旁只補必要解釋，不把圖表內容重新寫成長段文字。
- 未完成、重要風險、未知、未驗證與待確認事項直接呈現在正文，不藏進折疊區，也不把推論寫成已確認成果。
- 完整命令、測試輸出、逐項執行設定與較長證據放入 `<details>`，以清楚標題說明展開後的內容；正文保留結果、影響與證據入口。

## 選擇呈現方式

| 要說明的內容 | 優先形式 |
|---|---|
| 判斷邏輯或演算法 | 精簡虛擬碼（Pseudocode） |
| 執行順序或呼叫關係 | 呼叫樹（Call Tree），呈現哪個函式呼叫哪個函式 |
| 畫面組成與狀態邊界 | 元件樹（Component Tree），呈現畫面由哪些元件組成及其包含關係 |
| 檔案位置與模組責任 | 附繁體中文用途備註的淺層目錄樹（File Tree） |
| 元件互動、控制流程或資料流 | Mermaid 流程圖（Flowchart）或循序圖（Sequence Diagram） |
| 方案、責任、需求完成狀態或驗證結果 | 精簡表格（Table） |
| 修改前後差異 | 前後對照（Before/After）或差異片段（Diff）；大部分為新內容或省略會誤解時，顯示完整的必要區塊 |
| 圖表難以說明的畫面、版面或狀態比較 | 在同一份 HTML 中加入聚焦的視覺區塊（HTML Visual） |

只保留與本次報告相關的節點、欄位、狀態與邊界。使用真實標籤與已查證資料，不捏造數字或修改前結果。

## HTML 呈現

- 在呼叫方指定的同一份 HTML 中呈現，支援桌面與窄螢幕；已有產品視覺風格時沿用其配色、字體與間距，沒有時使用白底深色文字、系統字體、清楚標題與適當留白的簡潔版面。
- 圖表無法載入時，仍能從相鄰短句或表格理解結論；不只用顏色傳達狀態。
- 完成前確認報告可開啟、正文精簡、細節可展開，且呼叫方要求的資訊完整保留。
