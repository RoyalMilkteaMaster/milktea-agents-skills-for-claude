# Milktea Skills Check Feasibility

先查證，再判定是否值得進入規格與實作。成功代表在已確認的環境、成本與時間內通過驗收。

## 流程

1. 讀取 `docs/planning/requirements.md`、`docs/planning/architecture.md`、專案指令、程式庫、`CONTEXT.md` 與 ADR。
2. 查證技術能力、既有實作、外部依賴、權限、資料、硬體與目前價格。
3. 分別評估技術、架構相容、依賴、驗證、成本、時間與主要風險。
4. 依證據選擇一個成功機率區間，不給虛假的精確百分比。
5. 使用 `docs/feasibility/<名稱>.md` 與 `docs/assets/feasibility/`。
6. 寫入時才建立所需目錄，並把本 Skill 的六個 SVG 複製到文件資產目錄；不得讓報告連回 Skill 安裝路徑。
7. 顯示報告並取得使用者核准，再依分級關卡決定是否進入 `to-spec`。

價格或外部能力可能變動時，查官方來源並註明查證日期。無法確認就寫「不知道」。

## 分級

區間下限包含、上限不包含；100% 包含在最後一級。

| 成功機率區間 | 圖示 | 判定 |
|---|---|---|
| 0%–12.5% | `assets/red.svg`／🔴 | 幾乎完全不可能 |
| 12.5%–37.5% | `assets/red-yellow.svg`／🟠 | 難度偏高 |
| 37.5%–62.5% | `assets/yellow.svg`／🟡 | 難度中間 |
| 62.5%–87.5% | `assets/yellow-green.svg`／🟡🟢 | 難度還可以，成功機率偏高 |
| 87.5%–100% | `assets/green.svg`／🟢 | 成功機率非常高 |
| 無足夠證據 | `assets/unknown.svg`／⚪ | 無法評估 |

報告使用 `../assets/feasibility/<檔名>.svg`。無法顯示 SVG 時使用備用符號與文字，不得只靠顏色傳達結果。

## 判定規則

- 百分比是工程估計區間，不是統計保證。
- 列出支持證據、反對證據、假設與未知。
- 不取各項平均；單一關鍵阻擋可以限制整體上限。
- 核心依賴未驗證或成功定義不清時，使用「無法評估」。
- 成本寫金額區間；無可靠價格時只寫低／中／高並說明原因。
- 時間寫區間與前提，分開標示實作時間和外部等待時間。
- 提供最小的降風險方法：縮小範圍、原型、研究或停止。

## 分級關卡

- 🔴：停止；先提出可行替代方案。只有使用者明確接受極低成功率才能繼續。
- 🟠：預設先縮小範圍或驗證關鍵假設；使用者明確接受風險後才能繼續。
- 🟡：列出優先驗證項目；使用者核准後可繼續。
- 🟡🟢／🟢：使用者核准後繼續。
- ⚪：停止；補齊關鍵證據後重新評估。

## 完成條件

- 報告頂部有圖示、判定與區間。
- 成本、時間、證據、假設與未知均已說明。
- 沒有把猜測寫成精確機率。
- 使用者核准報告與後續處置。
