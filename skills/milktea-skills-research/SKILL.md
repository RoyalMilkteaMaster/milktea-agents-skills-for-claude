# Milktea Skills Research

把需要跨階段保存、交接或重用的研究結果整理成一份附引用的 Markdown。本 Skill 是按需證據工具，不是 Grill-me、Implement 或 Brownfield 流程的固定階段。

## 使用條件

只有下列任一情況成立時才使用：

- 使用者明確要求一份研究文件。
- 研究結果需要交給後續 Task、Agent、Spec、Ticket、實作或 Review 重用。
- 多個角色需要引用同一份外部證據，才能處理技術分歧。

如果只是回答當下的不確定事實，由目前 Agent 直接查證並繼續工作；不建立研究文件，也不增加 Agent。

## 研究方式

1. 確認明確的研究問題、研究結果的用途與實際輸出路徑。沿用呼叫者提供的工作目錄或專案既有慣例，不另建第二個工作包。
2. 背景或獨立 Agent 可用，而且研究可與其他工作並行時，將研究交給該 Agent；否則由目前 Agent 完成。不得只因無法建立額外 Agent 就停止查證。
3. 優先查官方文件、原始碼、正式規格與第一方 API。每個重要主張都引用真正擁有該資訊的來源，不以轉述文章代替可取得的第一手來源。
4. 與目前專案行為有關的事實，直接檢查實際程式庫、設定、Runtime 或可重現輸出，不用外部文件猜測本機狀態。
5. 分清楚已確認事實、仍有衝突的證據與無法確認之處；不知道就明確寫不知道。

## 輸出

- 把本次研究寫成一份 Markdown，格式依問題調整，但必須包含研究問題、精簡結論、逐項引用的證據，以及存在時的衝突或未知事項。
- 只保留這一份研究文件，不再建立摘要副本、資料庫、Ticket 或第二份報告。
- 回報實際檔案路徑，讓呼叫者自行用研究結果完成需求、架構、實作或 Review 判斷。

## 邊界

- 只研究呼叫者交付的問題，不自行擴大成完整市場、產品或架構研究。
- 不決定產品取捨、需求、架構、是否實作或 Finding 結論。
- 除研究文件外，不修改程式、Spec、Tickets、設定或其他專案檔案。
